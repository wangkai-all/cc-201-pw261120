# 语料工坊

一个可回查原文的语料切分对照网页。上传本地文本，按规则切段、切块并保留重叠；
每个片段都能指回它在**原始文件**中的准确起止位置，即使清洗过程改变了字符长度。

不调用任何语言模型，项目自带三篇合成文章作为样例。

## 快速开始

```bash
npm start          # http://127.0.0.1:3000
npm test           # 文本引擎与业务层的 18 个自动化测试
npm run smoke      # 起一个临时服务跑完整业务闭环
```

要求 Node.js ≥ 22.5（使用内置 `node:sqlite`，无第三方依赖）。数据默认写入
`data/corpus.db`（SQLite，WAL 模式）；可用 `PORT` 与 `DB_PATH` 环境变量覆盖。

首次打开页面是空库，点「载入三篇合成样例」即可看到完整效果。

## 核心设计

### 1. 原文 → 清洗文本的双向映射

清洗包含两步：Unicode 规范化（可选 NFC/NFD/NFKC/NFKD）和换行统一
（LF / CRLF / 保持原样）。两步都可能改变 UTF-16 长度，例如：

| 原文 | NFC 后 | 长度变化 |
| --- | --- | --- |
| `e` + 组合重音 U+0301 | `é` | 2 → 1 |
| `½` | `1⁄2`（NFKC） | 1 → 3 |
| `\r\n` | `\n` | 2 → 1 |

实现方式：以**原始文本的每个扩展字素簇**作为原子，逐个原子清洗。原子表同时记录
`rawStarts[]` 与 `cleanStarts[]` 两条单调偏移数组，因此：

- 任意清洗偏移区间都能二分回原文区间（`cleanToRaw`），反向同理；
- 一个原子可能变长或变短，但永远对应回同一段原文；
- 切片边界只落在原子边界上，不会切开代理对、组合字符序列或合成的 Hangul 音节。

“字符数”的统计单位是**清洗后文本的字素簇**，与原文字素簇一一对应。一个
`👨‍👩‍👧‍👦` 记 1 个字符，而不是 11 个码元。

### 2. 段落与重叠切分

- 段落模式：空行分段（默认）、每行一段、自定义正则分隔；
- 可选去除段落首尾空白（按原子裁剪，仍保持映射）；
- 每个段落按 `maxChars` 切成不超过上限的窗口；
- 第二块起，从上一块尾部复制 `overlapChars` 个字符作为重叠前缀。

每个片段同时记录：清洗区间、原文区间、核心区间、重叠区间的四种坐标，以及
内容 SHA-256。前端在原文视图中用三层高亮区分「当前片段核心 / 重叠 / 跨文档共享」，
点击原文任意字符会反查落到哪个片段。

### 3. 跨文档共享但保留来源

片段内容按 SHA-256 存入 `chunks` 表；`chunk_refs` 按
`(revision, position)` 记录每次引用及其文档、段落、坐标。

- 相同内容只存一份，但每个文档各有独立引用行；
- 删除文档只删它自己的 `revisions` / `chunk_refs`，随后回收**没有任何引用**的内容行；
- 被其他文档仍引用的内容不受影响，界面会显示剩余的来源数量。

### 4. 规则版本与增量重算

保存规则会创建新版本（配置完全相同时拒绝创建）。应用规则时：

1. `impact` 先对每个文档判断是否需要重切：
   - 清洗文本变了 → 需要；
   - 段落边界变了 → 需要；
   - 块长/重叠参数没变 → 复用；
   - 参数变了，但所有段落都不超过新旧块长 → 复用（切分结果等价）；
   - 否则 → 重切。
2. `recalculate` 只为受影响文档重切，其余文档复用原切分窗口并重新映射坐标，
   但仍会生成指向新规则版本的新 revision，保证导出时规则版本一致。
3. 重复应用同一规则时全部跳过，不会产生多余重切。

「版本对比」按内容哈希给出新增 / 消失 / 保留三组片段，并标明两个版本的规则号与
切分布局是否一致。

### 5. 训练清单导出

`GET /api/export` 返回 `corpus-manifest/1` 格式：

```json
{
  "format": "corpus-manifest/1",
  "documentCount": 3,
  "chunkCount": 26,
  "chunks": [
    {
      "id": "doc_…:0",
      "documentId": "doc_…",
      "documentName": "城市夜航",
      "revisionId": "rev_…",
      "ruleVersion": 1,
      "position": 0,
      "paragraph": 0,
      "contentHash": "…",
      "charCount": 4,
      "overlapChars": 0,
      "rawStart": 0,
      "rawEnd": 4,
      "text": "城市夜航"
    }
  ]
}
```

页面可下载 JSONL（每行一个片段）或复制完整 JSON。

## 页面功能

- **上传**：拖入 `.txt` / `.md` 或粘贴文本，可选择载入时使用的规则；
- **规则预览**：不落库，直接展示候选规则的段落数、块数、清洗长度变化与逐块切分；
- **原文高亮**：点击片段跳转到原文并高亮核心与重叠；点击原文反查片段；
  行首显示原文偏移，行尾标注该行原始换行类型（LF / CRLF / CR / U+2028 / U+2029 / U+0085）；
- **片段详情**：四种坐标、真正的原文切片、片段内被清洗改变的字符（码点级）、
  共享来源与复制按钮；
- **跨文档引用**：列出本文件的重复片段与其他文档的来源，可跳转；
- **版本**：历史列表与两两对比（新增 / 消失 / 保留）；
- **规则变更**：保存新版本 → 影响预演 → 只重算受影响文档或全部应用；
- **导出**：训练清单预览、JSONL 下载、JSON 复制。

## 目录结构

```
src/text.js      清洗映射、段落解析、切分、复用判定（纯函数，无 I/O）
src/store.js     SQLite 模式与查询（文档 / 规则 / 版本 / 内容寻址片段 / 引用 / 作业）
src/service.js   业务编排：上传、预览、影响预演、重算、对比、导出
src/server.js    内置 HTTP 服务与 JSON API
public/          无构建步骤的原生前端（HTML / CSS / ES module）
samples/         三篇合成文章：CRLF、LF、混合 CR/CRLF，含表情、组合字符、兼容字符
test/            node:test 自动化测试
scripts/smoke.js 端到端业务冒烟脚本
```

## API 摘要

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/state` | 文档、规则、作业、统计汇总 |
| POST | `/api/documents` | 上传文本并切分 |
| GET | `/api/documents/:id` | 文档 + 当前版本 + 片段 + 共享信息 |
| PATCH / DELETE | `/api/documents/:id` | 重命名 / 软删除（含内容回收） |
| POST | `/api/documents/:id/preview` | 候选规则预览（不落库） |
| POST | `/api/documents/:id/reanalyze` | 按最新或指定规则生成新版本 |
| GET | `/api/documents/:id/compare?left=&right=` | 版本差异 |
| GET | `/api/documents/:id/chunks/:revisionId/:position` | 单片段详情与来源 |
| GET / POST | `/api/rules` | 规则列表 / 保存新版本 |
| GET | `/api/rules/:id/impact` | 影响预演 |
| POST | `/api/rules/:id/recalculate` | 重算（可限定 documentIds） |
| GET | `/api/chunks/:hash` | 内容及其全部当前来源 |
| GET | `/api/export` | 训练清单 |
| POST | `/api/samples/load` | 载入合成样例（重复调用不会重复建文档） |

## 已知边界

- 单文档上限 50 万个 UTF-16 单元，块长上限 4000 字符，单文档片段上限 2 万；
  这是演示用的保护，不是算法限制。
- 片段重叠从上一块尾部精确复制；极短段落的末块会自然缩短核心长度，
  不会把重叠扩展到超过块本身。
- 正则分隔允许跨字素簇匹配，这种情况下会明确报错而不是静默错位。
- 页面不是多人协作系统；所有写操作串行落在单进程的 SQLite 上。
